# 役職別マネジメント画面「四領の書」設計書

作成: 2026-09-13 / 版: **v1.6**（官位・功を廃し、戦勝・制圧・金へ）

---

## 1. これは何か

芳川恒徳（よしかわ つねのり）さんが兼務する役職を、**1人の主人公が複数の領地を治める**構図に置き換えた、タスク進捗の管理画面。見た目はドラゴンクエスト風（黒背景・白二重枠・ドットフォント）。ブラウザ上で直接タスクを追加・完了でき、データはサーバ側に保存される。

「RPG風にする」ことの実利は3つ。

1. **開くのが億劫でなくなる** — 管理画面は開かれなければ機能しない
2. **抽象度の違う責任が、同じ尺度で並ぶ** — 執行と監査を同じ表に並べるのは本来やりにくい。領地という比喩がそれを可能にする
3. **状態が一目で分かる** — 数字の羅列より、枠が赤い領地が1つある方が速い

## 2. 領地の構成

### 2-1. 役職の性質は2種類に割れる

| 領地 | 実体 | 性質 | タスクの駆動源 |
|---|---|---|---|
| **HAL** | 行政書士法人HAL 役員 | 執行 | 常時攻略。自分が動かす |
| **GEMA** | 外国人材雇用マネジメント協会 代表理事 | 執行 | 常時攻略。自分が動かす |
| **海羽会** | 医療法人社団海羽会 監事 | 監査 | 期日駆動。理事会・決算・監査報告 |
| **APSIP** | 国際人材普及振興協会 監事 | 監査 | 期日駆動。理事会・決算・監査報告 |

**執行領地**は積んで消化する。**監査領地**は年間の決まった巡回で動く。監事の仕事は常時タスクが湧くものではないので、同じ「攻略率」で並べると常に空に見え、逆に期日を見落とす。よって領地カードの中身を出し分ける。

### 2-2. 44件を分類して分かったこと ─ 領地が足りない

既存のAI取り組み44件を4領地に割り当てようとすると、**半分近くがどこにも入らない**。

| 分類 | 件数 | 例 |
|---|---|---|
| HAL | 約13 | 外国人業務部の営業計画、書類回収アプリ、Software Factory、HPコラム全50回、医療福祉集客、人事評価制度、特定技能転職の上流獲得 |
| GEMA | 約6 | 協会の営業計画、プレミアム会員設計、gmane.or.jpサイト、LPコピー |
| 海羽会 | 0 | （巡回のみ） |
| APSIP | 0 | （巡回のみ） |
| **どこにも入らない①：個人名義の発信・教材（→ Awillize）** | 約12 | note連載GCシリーズ、Xポスト、オウンドメディア、ショート動画、Kindle出版、NOMA講義、社労士会研修、行政書士の学校、介護BC、外食業ワークブック、N2教材 |
| **どこにも入らない②：AI基盤・実験** | 約8 | Business OS、議事録パイプライン、JARVIS、サブエージェント可視化、メモリ管理、AIポートフォリオボード |

**提案**。この2つを次のように置く。

**① 個人名義の発信・教材 → 第5の領地「Awillize」**（屋号どおり）
実態として、HALの集客でもGEMAの集客でもあり、どちらか一方には畳めない。芳川恒徳個人の名前で立っている以上、独立した領地として持つのが素直。

**② AI基盤・実験 → 領地ではなく「工房」**
これは攻略対象ではなく、**主人公を強くする装備を鍛える場所**。JARVISもBusiness OSも、それ自体が成果ではなく他の領地の攻略速度を上げるためのもの。ドラクエでも「そうび」は町やダンジョンとは別のメニューにある。領地カードと同列に並べると、何をやっているのか分からなくなる。

結果、画面の構成は次のようになる。

```
執行  ┌ HAL ┐ ┌ GEMA ┐ ┌ Awillize ┐
監査  ┌ 海羽会 ┐ ┌ APSIP ┐
別枠  [ 工房 — そうびをきたえる ]
```

上段3・下段2に自然に割れ、性質の違いがそのままレイアウトになる。

## 3. ゲーム要素と実務の対応

| ゲーム側 | 実務側 | 算出 |
|---|---|---|
| 主人公 | よしかわつねのり | — |
| レベル | 積み上げた実行量 | 累積EXPから算出 |
| EXP | タスク完了で獲得 | 難易度 × 10。メインは×1.5、期日内完了で+20% |
| ゴールド | 完了の累計（軽い報酬） | 難易度 × 5 |
| クエスト | タスク | メイン／サブ／デイリー |
| メインクエスト | 期日があり外せないもの（理事会、決算、監査報告、登記、申請期限） | — |
| サブクエスト | 進めたい施策 | — |
| デイリー | 日次ルーチン | 繰り返し |
| 巡回イベント | 監査領地の年間スケジュール | 後述 |
| ボス戦 | 大きな期日イベント（決算理事会など） | 期日30日前から画面上部に出現 |
| そうび | AI基盤・実験（工房） | 領地とは別枠 |

### レベル

```
次のレベルまでの必要EXP = 100 + 50 × (現在Lv − 1)
```
Lv2まで100、Lv3まで150、Lv4まで200。序盤は軽く上がる。

### 緊急度の表現 ─ HPバーは廃止

v0.1では「領地HP」で健全度を出す案だったが、**指標を1つ増やすと、その指標の意味を思い出すコストが毎回かかる**。結局見るのは「期限を切ったものがあるか」「次の期日はいつか」の2つなので、専用の数値は置かない。

代わりに**領地カードの枠色**で出す。ドラクエのウィンドウ枠はもともと白なので、色が変わること自体が異常の合図になる。

| 枠色 | 条件 |
|---|---|
| 白 | 平常 |
| 黄 `#ffe14d` | 3日以内に期日のクエストがある |
| 赤 `#ff5a5a` | 期限超過のクエストがある |

| 回 | 日付 |
|---|---|
| 今期第1回 | **2026/9/18（金）** |
| 第2回・第3回 | 未定 |

### 2つの監事は、同じ「監査」ではない

実務を聞いて分かったのは、**この2つの負荷がまったく違う**こと。

| | 海羽会 | APSIP |
|---|---|---|
| やること | 理事会用に①会議資料 ②社員総会議事録 ③理事会議事録を作る、ほぼこれだけ | 業務監査・財務監査を海羽会より本格的に。加えて請求書等のチェックを随時 |
| 駆動 | **完全に巡回駆動** | 巡回＋**常時** |
| 最初の一歩 | ─ | Microsoftアカウントにログインできるようにする |

海羽会は巡回にぶら下げた準備クエストだけで足りる。APSIPは巡回に紐づかない常時タスクを持つので、**監査領地のカードに「じょうじ」行を追加**した。これがないとAPSIPのカードが「次は9/18、準備なし」としか言わず、本当にやるべき監査が画面から消える。

APSIPのログイン開通は、他の全部がそこで止まっている**関門クエスト**。期日は入れていないが、ここが開かないと業務監査も財務監査も始まらない。

監事の取りこぼしは、当日を忘れるより**前日に資料を読んでいない**形で起きる。準備クエスト側を見せる設計にする理由がそこにある。

## 10. モジュール管理（収益の本線）

領地とクエストは「いま何をやるか」の管理だが、それとは別に**収益がどう流れているか**を見る必要がある。

### 構造 ─ 入口は増えるが、本線は1本

当初は1本のファネルとして設計していたが、実態は違った。**フロントセミナーをいくつも作り、そのすべてが同じ教育導線と同じオファーに合流する。**

```
          集客どうせん（X・note・メルマガ・紹介）  ← 共通
                          ↓
   ┌ セミナー① ┐ ┌ セミナー② ┐ ┌ セミナー③ ┐   ← 入口・増える
   │ 申込LP     │ │ 申込LP     │ │ 申込LP     │
   │ 申込フォーム│ │ 申込フォーム│ │ 申込フォーム│
   │ リマインド  │ │ リマインド  │ │ リマインド  │
   │ 本番        │ │ 本番        │ │ 本番        │
   │ アーカイブ  │ │ アーカイブ  │ │ アーカイブ  │
   └────────────┘ └────────────┘ └────────────┘
        └──────────── ごうりゅう ────────────┘
                          ↓
        メルマガステップ・ステップLINE（教育）      ← 1本
                          ↓
        協会プレミアム会員オファー（販売）          ← 1本
                          ↓
                        継続
```

この形にした理由が、次の優先度ロジックに直結する。

### 画面がまず言うこと ─ 本線の欠けと入口の欠けは重さが違う

一番上に出すのは件数ではなく、**次に手を入れるべき1点**。ただしどこが欠けているかで意味がまったく違う。

| 状態 | 画面が言うこと | なぜ最優先か |
|---|---|---|
| 本線（教育・販売・継続）に未稼働がある | 「ほんせんが とまっています：販売 / 決済ページ」 | 本線は1本。ここが欠けていると**セミナーを何本作っても全部無駄になる** |
| 本線は揃っているが稼働中の入口がゼロ | 「かどうちゅうの いりぐちが ありません」 | 器はあるが流入がない |
| 集客導線が止まっている | 「しゅうきゃくどうせんが とまっています」 | 入口に人が来ない |

セミナーを増やすのは楽しいので手が向きやすいが、本線が欠けていれば増やすほど取りこぼしが増える。画面がそれを止める。

### 入口カード

フロントセミナー1本につき1枚。名前・状態（未着手／制作中／稼働中）・開催日・**申込数と参加数、その通過率**を持つ。中にモジュール（申込LP／申込フォーム／リマインド／本番／アーカイブ）が並ぶ。

「フロントセミナーを ふやす」を押すと、この5モジュールが自動で付いてくる。セミナーを1本増やすたびに同じ作業が発生するので、そこは型にした。

### 合流

入口と本線の境目に帯を1本引き、**全セミナーの参加数の合計**を出す。ここが本線に流れ込む母数になるので、本線側の通過率はすべてこの数字を起点に計算する。

### 本線のモジュールと通過率

教育・販売・継続のモジュールは、数値の名前と値を自分で決められる。数値が入ったモジュールが続く区間では、前のモジュールに対する通過率を自動で出す。合流100 → オファーLP到達45 なら45%。

### 数値の入力 ─ 手入力から自動化へ

現状は手入力。自動化の道筋は次のとおり。

1. このボードのデータは外部から書き込める。Claude側から入口の申込・参加数や本線の数値を直接更新できる
2. したがって「UTAGEから数字を拾ってボードに書き込む」を定期実行タスクにできる
3. ただし**UTAGEの管理画面の構造を見ていないので、まだ組めない**。ブラウザ操作で拾うのか、CSVエクスポートを経由するのかは実物を見て決める

### 型としての再利用

ファネルは複数持てる。介護BCや特定技能2号対策講座も、同じ「共通の集客 → 複数の入口 → 合流 → 1本の本線」の型に流し込める。

## 11. 軍師（担当AIマネージャー）

各領地とルートマップに**担当のAIマネージャー**を置き、その画面から直接プロンプトを打てるようにした。ゲーム側の呼び名は「軍師」。

### なぜ画面ごとに分けるか

1つの万能アシスタントではなく、領地ごとに別の軍師を置いた。理由は2つ。

**役割の性質が違う。** 監事の補佐に「施策を広げる提案」をされても邪魔なだけだし、発信の軍師に法令の期限管理をさせても筋が悪い。役割は画面ごとに固定したほうが精度が上がる。

**状況が自動で渡る。** その領地のクエスト・期日・巡回、ルートマップならモジュールの状態と数値が、プロンプトと一緒に自動で送られる。だから「今の状況を説明する」手間がいらない。「この順番でいいか」と打つだけで、実データを見た答えが返る。

### 初期の7人

| 画面 | 軍師 | 軸 |
|---|---|---|
| HAL | HALのぐんし | 受注につながるか／人手を増やさず回るか。法令期限は常に最優先 |
| GEMA | 協会のぐんし | 新規入会より、入った人が続ける理由があるかを先に見る |
| Awillize | 発信のぐんし | 本数を増やすより、今あるコンテンツが仕事につながっているか |
| 海羽会 | 海羽の監事補佐 | 期日と議事録の記載事項。やることを勝手に広げない |
| APSIP | APSIPの監事補佐 | 監査の手順と見るべき資料。ログイン開通が全ての前提 |
| 工房 | かじや | 「これはどの領地の何を早くするのか」を常に問う |
| モジュール管理 | 導線の軍師 | 本線の欠け＞入口の数。数字が未入力なら推測せず名指しする |

名前も役割文も画面から書き換えられる。役割文がそのままClaudeへの指示になる。

### クエストを実際に登録できる

領地の軍師には**add_quest**を持たせた。「10/1の理事会準備を分解して」と打つと、提案するだけでなく実際にクエストとして登録される。分解した結果を手で打ち直す必要がない。

登録は元に戻せる（クエスト一覧から「すてる」）ので、取り消しのきかない操作はさせていない。

### 制約 ─ 先に知っておくべきこと

- **このチャットとは別物。** 画面の軍師はこの会話を知らないし、会話をまたいで記憶もしない。渡されるのはその画面の状況と、その場のやりとりだけ
- **芳川さんのClaude利用枠を使う。** 初回に許可を求められる
- **やりとりは保存されない。** 画面を閉じれば消える。残したいものはクエストにする
- 答えに時間がかかる（5〜60秒）。クエスト登録を伴うときはもっとかかる。途中で「やめる」で止められる

## 12. 資料棚 ─ ファイルを軍師に渡す

Claude Codeのようにファイルやフォルダを指定して軍師に読ませたい、という要望への対応。

### まず、できないこと

**Macのローカルパス（`~/Documents/...`）は指定できない。** このボードはブラウザのページとして動いていて、ページからパソコンのファイルシステムを読むことはブラウザが許していない。Claude Codeがパスを指定できるのは、あれがMac上で直接動いているから。ここは仕組みが違う。

### 代わりに置いたもの ─ 領地ごとの資料棚

「毎回ファイルを選び直す」のではなく、**領地に資料を置いておく**形にした。フォルダ指定に一番近い動きになる。

- 各領地とルートマップの軍師の窓に「しりょうだな」がある
- PDF・Word（.docx）・PowerPoint（.pptx）・テキスト系（txt・md・csv・tsv・json・yaml・html・xml・log）をドロップするか選ぶと、棚に残る
- 棚の各ファイルにチェックボックスがあり、**入っているものだけが軍師に渡る**
- 一度置けば次回以降も残る。営業計画、議事録の前回分、コラムの構成表などを置いておけば、毎回添付せずに済む

チェックボックスにした理由は、資料が増えると全部渡すのが逆に邪魔になるから。今回の質問に関係あるものだけを選んで渡せる。

### 画像はその場かぎり

画像（PNG・JPEG）もドロップできるが、こちらは**その1回の質問にだけ添付**され、棚には残らない。UTAGEやkintoneの画面を撮って「これどう読む？」と聞く用途を想定している。

### 容量の扱い

- 1ファイルあたり20,000字まで保存。超える分は先頭のみ（棚に「先頭のみ」と出る）
- 軍師に渡す合計は24,000字まで。超えると入れた順に打ち切る

プロンプト全体に上限があるので、長大なファイルを丸ごと渡すことはできない。章ごとに分ける、要約を置く、といった使い方になる。

### 次の一手 ─ Google Drive連携

Google Driveを繋げば、**Drive上のフォルダやファイルを指定して読ませる**ことができる。仕組みとしては、ページから芳川さんのDriveコネクタを呼び出す形。

ただし実装前に、Driveのツールが実際にどんな形でファイル一覧や本文を返すかを一度確認する必要がある。推測で組むと動かない。やるなら先にそこを確かめる。

- **武将に命じる** ─ 成果物そのものを作らせる。答えは下書き・手順表・文面

任務の行に「命じる」が付いた。押すと武将を選び、補足を添えて命を下せる。返ってきたものは「報告として残す」で任務に紐づき、以後は行に「報 1」と出て読み返せる。

## 15. 命令書 ─ Claude Codeへの受け渡し

### ページからClaude Codeを直接叩けるか

**叩けない。** このボードはブラウザのページで、Mac上のアプリを起動する手段を持たない。プロンプトを送り込む口もない。

### 代わりに置いたもの

任務の行に**「命令書」**を付けた。押すと、そのままClaude Codeに貼れる指示文が組み上がる。

```
# 依頼
理事会の会議資料の作成

# 背景
領地: 海羽会（医療法人社団海羽会 監事）
種別: 主命　難度: ★3　期日: 2026-10-01
今日: 2026-09-13

# 読んでほしいファイル
- ~/Documents/海羽会/前回議事録.md
- ~/Documents/海羽会/決算資料.xlsx

# 配下の下書き（書記）
（報告があれば先頭2,000字）

# 求めるもの
（ここに、何をどこまでやってほしいかを書き足してください）
```

パスは書庫の「場所の控え」から自動で拾う。配下に命じて下書きを作らせていれば、それも一緒に入る。「写す」でクリップボードに入るので、Claude Codeに貼って続きをやらせる。

軍師の答え、武将の成果、残した報告にも「写す」を付けた。

### この設計の位置づけ

ボードは**考えて決める場所**、Claude Codeは**手を動かす場所**。境界をまたぐのは人間の貼り付け一回ぶんだけにした。パスと文脈が毎回そろっているので、Claude Code側で状況説明をやり直さずに済む。

### もう一つの道

このチャット（Cowork）は芳川さんのMacと繋がっている。フォルダを一つ許可してもらえれば、**ここから直接ファイルを読んで書き換えられる**。Claude Codeを経由しない分こちらのほうが速い場面もある。用途で使い分ける。

## 17. 書庫の対応形式（v1.3）

テキストしか受け付けなかった書庫を、**PDF・Word（.docx）・PowerPoint（.pptx）**に広げた。

### やり方

ブラウザの中で本文を取り出してから棚に納める。ファイルそのものを持つのではなく、**取り出した文字だけ**を保存する。

| 形式 | 取り出し方 |
|---|---|
| PDF | pdf.js をその場で読み込み、ページごとに本文を抽出（最大100ページ） |
| .docx | JSZip で展開し、`word/document.xml` の段落を拾う |
| .pptx | JSZip で展開し、スライドごとに本文を拾って「## スライド n」で区切る |

ライブラリは**ドロップされた瞬間に読み込む**ようにした。常時読み込むと、テキストしか置かない日も待たされる。

### 読めないもの

- **画像だけのPDF**（スキャンした紙）は文字が入っていないので取り出せない。その旨を書庫に表示する
- **.doc（旧形式）・.xls・.xlsx** は未対応。`.docx` に保存し直すか、表計算はCSVで出すよう案内する。旧Word形式は構造がまったく別で、無理に読むと文字化けした断片が混ざり、かえって軍師の判断を狂わせる
- Pages・Numbers・Keynote も同じ扱い

### 分量の目安

1ファイル20,000字までという上限は変わらない。PDFなら概ね30〜50ページ分に当たる。長い資料は章ごとに分けて納めるほうが、必要な部分だけ渡せて扱いやすい。

## 18. 進言を実行させる（v1.4）

軍師に相談して答えをもらったあと、**それを武将に渡して成果物にする**までを画面の中でつないだ。

### 置き場所

軍師の窓に答えが出ると、その下に「進言を実行させる」欄が現れる。

1. **誰に実行させるか** ─ AIの武将から選ぶ
2. **渡す指示** ─ 軍師の答えがそのまま入っている。**編集できる**。余計な前置きを削る、条件を書き足す、といった手当てをしてから渡せる
3. **命を下す** ─ 武将が成果物を書く

「進言を写し直す」で、編集前の状態に戻せる。

### 編集できることが要

軍師の答えをそのまま渡すと、たいてい前置きや「まず確認すべきは」といった判断部分まで指示として読まれてしまう。**渡す前に削れる**ことが、この欄の実用性を決める。武将には「進言を評したり言い換えたりせず、指示として実行せよ」と伝えてある。

### 成果の行き先

出てきた成果物は次のどちらかにできる。

- **写す** ─ クリップボードへ。Claude Codeや他の場所で続きをやる
- **報告として残す** ─ 任務に紐づける。既存の任務から選ぶか、「新しい任務として作る」を選べばその場で任務が立つ（題名は指示の1行目から取り、担当にその武将の名が入る）

これで、相談から成果物、そして任務の記録まで、画面を出ずに一周する。

### 流れ

```
軍師に相談する          → 方針が決まる
　↓ 進言を編集して渡す
武将が実行する          → 成果物ができる
　↓ 報告として残す
任務に紐づく            → 後から読み返せる
```

## 20. 本営の数字を実物に寄せる（v1.6）

### 官位と功をやめた

レベルと経験値は**架空の数字**で、増えても実務上の意味がなかった。完了すると増える、それだけのもの。本営の一番上に置く価値はない。

代わりに三つを並べた。

| 表示 | 中身 |
|---|---|
| **戦勝** | 完了したサブタスク（策）の数 |
| **制圧** | 完了したメインタスク（主命）の数 |
| **金** | 協会の預金残高（手入力） |

### なぜこれが効くか

戦勝と制圧を**分けて数える**ことに意味がある。策をいくら積んでも主命が動いていなければ、忙しいだけで何も終わっていない。一つの合計値にすると、その差が消える。

金は架空の報酬ではなく**協会の実際の預金残高**。会員制ビジネスの体力がそのまま出る。増えたか減ったかは施策の結果であって、タスクを消した褒美ではない。

金は「改める」から手で書き換える。自動では動かない。
